# switter для Android

Нативный Android-клиент для [one-loner/Switter](https://github.com/one-loner/Switter).
Название приложения — **switter**, иконка взята из `favicon.png` исходного репозитория.
Минимальная версия: **Android 8.0 (API 26)**. Интерфейс на 15 языках (16 локалей с египетским вариантом арабского), с выбором языка в настройках и автоматическим выбором по системе.

## Возможности

- Подключение своего блога с произвольным относительным путём или полным URL административного скрипта: `private-panel.php`, `/private/control.php`, `https://example.org/blog/manage.php`.
- Вход по логину и паролю, сессии PHP и автоматическое получение CSRF-токена.
- Публикация, удаление, добавление JPG/PNG/GIF/WEBP до 5 МБ, предпросмотр.
- Разметка Switter: `**жирный**`, `*курсив*`, `__подчёркнутый__`, `~~зачёркнутый~~`, `[текст](https://example.org)`.
- Архивирование всех текущих записей с подтверждением. Нативный просмотр списка и полных текстов архивов своего блога и подписок; веб-страница архива также доступна.
- Подписки, отдельные ленты блогов, общая лента своего блога и подписок от новых записей к старым.
- Обновление свайпом сверху вниз в ленте и веб-режиме. Ошибка одного блога не скрывает записи остальных; ранее прочитанные записи остаются в памяти до закрытия процесса.
- Чтение `posts.json`, затем распознавание HTML Switter; при несовместимой странице — встроенный веб-режим.
- Репост с редактированием текста, копированием изображения в свой блог и ссылкой на первоисточник. Изображение скачивается через настройки подключения источника, затем загружается через настройки своего блога.
- Поиск по заголовкам и текстам всех блогов ленты: кнопка с лупой сверху слева во вкладке «Лента». Опция «Глубокий поиск» дополнительно проверяет все доступные HTML-архивы. Ошибки отдельных блогов или файлов не скрывают найденные записи.
- Светлая, тёмная и системная темы.
- PIN из 4–12 цифр, подтверждение при установке и проверка текущего PIN при смене или отключении. Блокировка при уходе из приложения, нарастающая задержка после пяти неверных попыток.
- Отдельное прямое или SOCKS5-подключение для каждого блога. Поддерживаются SOCKS5-прокси **без логина и пароля**, в том числе Tor. Имена конечных сайтов разрешаются через прокси; при отказе прокси прямое подключение не используется.

## Установка и подключение

1. Установите `switter-1.1.0-debug.apk` на Android, разрешив установку из выбранного файлового менеджера.
2. Нажмите «Подключить мой блог». Укажите адрес главной страницы, путь к административному скрипту, логин и пароль. Клиент не требует переименования скрипта или установки серверного API.
3. Укажите часовой пояс PHP-сервера: например `Europe/Moscow` или `UTC`. Switter хранит `created_at` без часового пояса; это влияет на порядок общей ленты. Время на карточках показывается в часовом поясе телефона.
4. При необходимости включите SOCKS5 и введите хост и порт. Прокси должен быть доступен с телефона; `127.0.0.1` означает сам телефон, а не компьютер.
5. Через «Подписки» добавьте другие блоги. Для каждого задаются собственные прокси и часовой пояс.
6. В «Настройках» выберите язык интерфейса, тему и установите PIN.
7. Чтобы читать архив подписки, нажмите «Архив» в карточке подписки или в ленте выбранного блога. В ленте нажмите лупу и введите запрос. Включите «Глубокий поиск», чтобы включить архивы.

Адрес каталога блога должен выглядеть как `https://example.org/blog/`; поддерживается и `https://example.org/blog/index.php`. Путь каталога без завершающего `/` нормализуется при сохранении. Для обычного чтения можно добавлять только подписки, не подключая свой блог.

Перед репостом откроется редактор: проверьте текст, изображение и ссылку, затем нажмите «Опубликовать». Если изображение источника не удалось получить, выберите файл вручную или явно нажмите «Убрать».

## Особенности платформы

Исходные функции клиента реализованы по Switter `118558dbecfb801e3b917052d07915e4b630f371`. Чтение архивов и глубокий поиск добавлены по исходникам сервера `dee30144d90c661ecfa7789ca6ee02c905d77e86`.

- Серверное архивирование переносит **все** текущие записи в HTML-архив и очищает `posts.json` и текущие `uploads`. Клиент показывает это перед подтверждением. Обратного переноса через Switter нет.
- У платформы нет постоянных URL отдельных записей. Поэтому ссылка на первоисточник имеет вид `https://blog.example/?q=Заголовок`. Одинаковые заголовки могут дать несколько результатов; после архивирования поиск Switter включает архивы.
- Для удаления нужен ID из `posts.json`. Если сервер запрещает доступ к JSON и записи прочитаны из HTML, кнопка удаления для таких записей не показывается.
- Записи без даты отображаются в конце ленты с пометкой «дата не указана».
- Веб-режим показывает HTML и стили, поддерживает ссылки, масштабирование и обновление. JavaScript, файловый доступ и внешние приложения отключены; встроенные веб-формы администрирования не используются. Все удалённые ресурсы веб-режима загружаются транспортом выбранного блога.
- При сетевом обрыве после отправки формы результат может быть неопределённым. Автоматического повторения записи нет: обновите ленту перед повторной публикацией.
- Черновики и офлайн-лента не сохраняются между перезапусками процесса. При обычном повороте экрана редактор сохраняется; при выходе из редактора с текстом запрашивается подтверждение. Завершайте или копируйте текст перед закрытием приложения или сменой системной темы.

## Хранение и безопасность

Настройки подключения, пароли и параметры PIN находятся в зашифрованном хранилище AES-GCM с ключом Android Keystore. PIN проверяется через PBKDF2-HMAC-SHA256 с индивидуальной солью и 160 000 итераций. Счётчик попыток и задержка сохраняются между запусками.

PIN блокирует интерфейс; шифрование хранилища привязано к устройству и Keystore. Резервное копирование и перенос данных приложения исключены. Окно защищено от системных снимков экрана и отображения содержимого в списке последних приложений. Забытого PIN восстановить нельзя: очистка данных Android удалит настройки приложения, но не записи на сервере.

HTTPS использует стандартную проверку сертификатов. HTTP разрешён для совместимости с блогами и onion-сайтами; шифрование соединения определяется URL и используемой сетью. Сессии PHP хранятся только в памяти отдельного клиента каждого блога.

## Сборка

Требуются JDK 17, Android SDK Platform 35 и Build Tools 35.0.0. Откройте каталог проекта в Android Studio либо укажите SDK через `ANDROID_HOME` или `local.properties`:

```properties
sdk.dir=/path/to/Android/sdk
```

```sh
./gradlew assembleDebug testDebugUnitTest lintDebug
```

Gradle Wrapper 8.11.1 с проверкой SHA-256 включён. Android Gradle Plugin — 8.9.2.
APK: `app/build/outputs/apk/debug/app-debug.apk`.

Предоставленный APK подписан **отладочным** ключом и предназначен для установки и проверки. Для собственного распространения соберите release со своим постоянным ключом Android Studio: Build → Generate Signed Bundle / APK. Смена ключа подписи потребует удаления предыдущей установки и её локальных настроек.

## Тесты

```sh
./gradlew testDebugUnitTest lintDebug
./gradlew connectedDebugAndroidTest
```

Тесты протокола проверяют парсинг, даты и часовые пояса, сортировку, HTML-резервирование, ограничения изображений, вход с cookie и CSRF, произвольный административный путь, multipart-публикацию, удаление, архивирование, ошибки форм, запрет утечки данных через редирект, удалённое SOCKS5 DNS и отсутствие прямого подключения при отказе прокси.

Инструментальные тесты дополнительно проверяют реальный Android Keystore, PIN и задержку попыток, блокировку при уходе с экрана, две темы и загрузку CSS/изображений встроенного веб-режима через SOCKS5. Они используют локальные тестовые серверы, без обращения к настоящим пользовательским блогам. Проверка на действующем развёрнутом PHP-блоге не проводилась.

Контрольные изображения тем создаются на вымышленных данных тестами `DeviceTest.renderThemes`; они не содержат данных пользователя.

## Структура

- `MainActivity.java` — нативный интерфейс, ленты, редактор, PIN и веб-режим.
- `Network.java` — маршруты SOCKS5, HTTP, cookie, формы, CSRF, ограничения загрузок.
- `Content.java` — JSON/HTML, разметка, ссылки на источник, порядок ленты.
- `Vault.java` — Keystore, шифрование настроек, PIN и задержки.
- `Blog.java`, `Post.java` — модели подключения и записи.

Иконка: `favicon.png` из исходного Switter. Серверные PHP-файлы в проект приложения не включены.

## Языки интерфейса

15 языков, 16 локалей: английский (`en`), китайский, упрощённое письмо (`zh`), хинди (`hi`), испанский (`es`), стандартный арабский (`ar`), французский (`fr`), бенгальский (`bn`), португальский (`pt`), русский (`ru`), урду (`ur`), индонезийский (`id`), немецкий (`de`), японский (`ja`), нигерийский пиджин (`pcm`), египетский арабский (`ar-EG`), маратхи (`mr`).

Критерий выбора — общее число пользователей языка, включая второй язык, по [рейтингу Ethnologue 2025, опубликованному Visual Capitalist](https://www.visualcapitalist.com/ranked-the-worlds-most-spoken-languages-in-2025/). В этом рейтинге стандартный и египетский арабский учитываются отдельно. В приложении предусмотрены обе арабские локали и следующий язык рейтинга — маратхи: это даёт 15 отдельных языков и 16 локалей. Египетская локаль использует преимущественно стандартные арабские формулировки с отдельными египетскими элементами интерфейса.

Язык можно выбрать вручную либо оставить системный. На Android 13+ используется системный механизм языка приложения; на Android 8–12 — сохранённая локальная настройка. Арабский и урду поддерживают направление справа налево. Форматы дат и числовые подстановки используют локаль интерфейса. Все языки включены в APK и App Bundle; для переключения загрузка ресурсов не нужна. Тексты записей, имена блогов и содержимое серверных веб-страниц не переводятся.

Английский и русский тексты отредактированы при разработке. Остальные переводы подготовлены машинным переводом Google и языковой генерацией, с корректировкой терминов навигации; профессиональная вычитка носителями языка не проводилась. Проверка полноты ресурсов и подстановок:

```sh
python3 tools/verify_translations.py
```

## Особенности чтения архивов и поиска

Сервер менять не требуется. Список файлов читается из `archive/`, затем приложение загружает HTML выбранного архива. Изображения разрешаются относительно URL архива (`archive/uploads/`). Записи с одинаковыми заголовками в разных архивах остаются отдельными. Репост архивной записи ссылается на исходный HTML-файл; удаление архивных записей не предлагается.

Текущая версия сервера не сохраняет исходную дату и ID поста в HTML-архиве. Поэтому архивные записи показываются с пометкой «дата не указана», после датированных записей в результатах поиска. Не используется дата создания архива вместо даты публикации.

Поиск без учёта регистра проверяет заголовок и видимый текст записей, обновляя данные с серверов. При включённом глубоком поиске дополнительно скачиваются все доступные архивы всех блогов ленты. Это может занять время и расходовать трафик; работают индивидуальные настройки SOCKS5 каждого блога, в том числе для изображений. Результаты и ошибки отображаются по мере завершения проверки блогов. При ошибках результат частичный, ошибки видны рядом с найденными записями. Архивы и результаты поиска остаются в памяти процесса и не сохраняются на диск.
